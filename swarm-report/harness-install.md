## Адаптация

- Вызовы навыков переведены на `$plan`, `$build`, `$review`, `$debug`.
  Встроенная команда Codex `/plan` не является вызовом навыка `plan`.
- Claude `Task` / `subagent_type` заменены правилами использования доступных инструментов
  Codex. Роли являются инструкциями задач, а не автоматически зарегистрированными типами
  агентов; отдельная конфигурация агентов не требуется.
- При разрешенном делегировании допускаются субагенты с четким владением файлами.
  При отсутствии инструментов роли выполняет основной агент последовательно;
  самостоятельное ревью должно быть обозначено как self-review.
- Сохранены планирование с критической проверкой, маршрутизация исполнителей,
  review ship/rework и диагностика через воспроизведение и проверку гипотез.
- Проверки выбираются по реальным файлам проекта, без навязанных версий, облака или стека.
  Результаты команд требуют фактических свидетельств; недоступная проверка не считается
  успешной. Учтены staged/unstaged/untracked файлы и согласованный диапазон ревью.
- Повторное подтверждение уже разрешенной реализации не требуется; самостоятельные
  внешние действия не получают разрешение от одного лишь вызова навыка.
- Hooks, `.claude/settings.json`, setup, design-cover, visual-verify, design-reader,
  visual-critic и конфигурация design gate не установлены. Механическое блокирование
  завершения через Stop hooks не заявляется.

## Примеры вызова

```text
$plan Добавь CI для проверки Dockerfile. Используй slug docker-ci.
$build docker-ci
$review docker-ci
$debug Падает проверка Dockerfile в CI: <вставить реальный текст ошибки>
```

Ожидаемые артефакты первых трех вызовов: `swarm-report/docker-ci-plan.md`,
`swarm-report/docker-ci-build.md`, `swarm-report/docker-ci-review.md`.
Debug сохраняет `<slug>-debug.md`, используя slug задачи или slug симптома.
Примеры являются подсказками для будущих вызовов и не запускались при установке.
